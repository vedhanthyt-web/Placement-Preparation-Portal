Java OOP Concepts — Viva Examination Guide

Direct mapping of Object-Oriented principles implemented in this application for your viva

OOP Pillar 1

Encapsulation

Wrapping data (attributes) and code acting on data (methods) together as a single unit, keeping fields private and controlling access through getters/setters.

Project Classes: Student, User, Question, Result
  • All class attributes are declared private (e.g., private double cgpa;).
  • Mutator methods enforce integrity: setCgpa(double cgpa) throws an IllegalArgumentException if CGPA is outside 0.0 - 10.0.
  • Score tracking is encapsulated inside student.updatePerformance(score).
OOP Pillar 2

Inheritance

The mechanism by which one class acquires the properties and behaviors of a parent class ('is-a' relationship) promoting code reusability.

Project Hierarchy:
  • User (Parent) → Student (Child), Admin (Child).
  • Question (Parent) → AptitudeQuestion, LogicalQuestion, TechnicalQuestion.
  • Child classes invoke parent constructor via super(...) and inherit shared fields (name, email, questionText, marks).
OOP Pillar 3

Polymorphism (Runtime & Compile-Time)

The ability of an entity to take more than one form. Implemented via Dynamic Method Dispatch (Overriding) and Method Overloading.

Project Implementations:
  • Runtime Polymorphism (Overriding): In MockTestService, question.evaluateAnswer(chosen) is invoked on the base Question reference, executing specialized subclass logic at runtime.
  • Compile-Time Polymorphism (Overloading): PlacementDrive.isEligible(...) is overloaded: one takes Student student, while another takes (double cgpa, int backlogs).
OOP Pillar 4

Abstraction & Interfaces

Hiding implementation details and showing only essential features to the outside world through abstract classes and interfaces.

Project Implementations:
  • abstract class User defines public abstract String getRoleDescription();
  • abstract class Question defines public abstract String getCategory();
  • interface Evaluatable defines contract for question checking.
  • interface Scorable defines contract for percentage and grading.
  • interface Trackable defines contract for placement eligibility.
Core Java Concept

Constructors & Constructor Chaining

Special methods used to initialize objects. Constructor chaining ensures parent class state is initialized before child extensions.

Project Implementations:
  • Student constructor invokes super(name, email, password, "STUDENT").
  • TechnicalQuestion constructor calls super(...) with base question fields before assigning this.programmingLanguage.
Robustness

Custom Exceptions & Global Handling

Graceful error recovery and unified error messaging across all API layers.

Project Implementations:
  • ValidationException and ResourceNotFoundException extend RuntimeException.
  • @RestControllerAdvice GlobalExceptionHandler formats clean HTTP responses (400, 404, 500).
